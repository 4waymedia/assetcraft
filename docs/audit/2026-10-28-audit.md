# Audit: architecture, structure, performance and integrations (2026-10-28)

_2026-10-28 · Stage 1.5 / 2 / 4 / 3D V0 / pre-3.5 · findings open_

- **Scope:** Storyboard mode, the 3D viewer, the shared architecture, and readiness for Stage 3.5 Develop (photo editing), on `feat/a2c-1-cuemap` @ `ac232a6` plus the uncommitted F1b/F2 work; LightCraft at the pinned `16dbb90`.
- **Project goal it serves:** a fast, crash-proof AssetCraft that can take on Stage 2 writes and the Develop editor without rewrites, with crates ModelCraft and FilmCraft can share.
- **Immediate area of improvement:** one shared way to write files, a few per-frame hot spots, two small correctness bugs, and a corrected Develop plan before Stage 3.5 starts.

Method: four read-only agents (Storyboard, 3D viewer, cross-cutting, Develop readiness) worked in parallel; Claude spot-checked the load-bearing claims against the code (SB-9, SB-1, AR-2, AR-4, AR-5, V3-1, V3-6, DV-1, DV-6 confirmed) and merged duplicates. Nothing in the repo was changed by the audit. Evidence is `file:line` in this repo, or `lightcraft/<path> @16dbb90`.

## Verdict

The codebase is in good shape: layers are enforced and pass (15 crates), every action goes through `Session::execute`, never-crash rules are applied consistently, no file is over 952 lines, and hostile-input limits are everywhere. What it needs next is **foundations, not rewrites**:

1. One audited **file-write seam** (five hand-rolled atomic writers today; the cache one skips `fsync`). Stage 2 renames, Develop sidecars and undo all sit on it.
2. A few **per-frame costs** on the Start screen and in the 3D preview that will hurt on low-end machines.
3. Two **real bugs** (Re-cut keeps a stale audio edit; a panicking decoder stalls the analyser) and one I introduced (9 of 12 prefs fields only save on a clean exit).
4. A **corrected Develop plan**: LightCraft writes `lc:settings`, not `crs:`, and the raw-to-image colour path lives in `lightcraft-engine`.

Develop is **ready after two prerequisites** (the write seam with sidecar undo, and an upstream split or NOTICE'd copy of LightCraft's loader); its first two steps can start now.

## Strengths to keep

- **Layering is real.** `cargo xtask layers` passes (15 crates); the engine has no UI dependency; a new crate must take a layer decision first.
- **One door for state.** `Session::execute` with declared `Effects`; the CLI's `exec`, `commands`, `describe` expose the whole registry (66 commands); menus are checked against it in tests.
- **Hostile input everywhere.** Cue maps, glTF (checked arithmetic, whole-document budgets), `places.json`, Finder bookmarks: size caps, bounds checks, `.bad` set aside, `catch_unwind` around every thumbnail decoder.
- **Proven threading patterns to copy:** the shared per-track decode slot (`decode.rs`), the latest-wins model view with a tested drag-quality controller (`thumbs/src/model.rs`), and an audio callback that never waits (`playback`).
- **Pure domain crates.** `storyboard`, `analysis` and `mesh` have no I/O or UI and are wasm-friendly, which is what makes them shareable with FilmCraft and ModelCraft.
- **Writes stay out of user folders unless asked**, and tests prove it (analysis store, Copy import).

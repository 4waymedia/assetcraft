# Crafting Apps integration surfaces for AssetCraft: PhotoCraft, LightCraft, FilmCraft

Scope: every way an external Rust asset browser (AssetCraft) can drive, query or embed the three storytold
Crafting Apps at their latest release tags. This is a read-only source inventory: nothing was built, and the
clones were not modified. Each claim cites `file:line` relative to that app's clone root.

| App | Tag | Commit | Engine commands | UI-level commands | MCP tools | Control channel auth |
| --- | --- | --- | --- | --- | --- | --- |
| PhotoCraft | v0.9.0 | c699e3c | 863 | 76 (+ ids handled by `view_cmds`/`workspace_ui`/… `handles()`) | 25 | 256-bit bearer token (required) |
| LightCraft | v0.8.0 | 16dbb90 | 312 | 170 | 17 helpers + 11 connect-only + one `cmd_*` per command (unless `--compact`) | none |
| FilmCraft | v0.8.0 | f03e215 | 702 | 211 | 17 | none |

How the counts were made: no build was run, so the registries were read statically
(a static extractor script). The script takes every whitelisted spec constructor (`cmd!`, `spec!`, `spec(`, `query!`,
`filter_cmd!`, `section!`, `uic!`, …) whose first argument is an id literal, plus `CommandSpec { id: "…" | CONST }`
literals. Ids generated by `format!`/`concat!` were expanded by hand (PhotoCraft adjustment, layer-style,
stack-mode and type-style families; FilmCraft `camera_keys!`). Test modules are excluded. Expect a margin of a few
ids. The live, authoritative list is `engine.commands` / `command_list` / `<app>-cli commands --json`.

Cross-app conventions (the shared "filmcraft #28" MCP conventions, cited in `pc/docs/mcp.md:3` and
`lightcraft/docs/mcp.md:126`):
- Every app has a JSON-lines control server on loopback with the envelope `{"id","method","params"}` →
  `{"id","ok","result"|"error"}`, plus `engine.execute {command, params}`, `engine.commands`, `ui.inspect` and
  `ui.screenshot`.
- Every app has a headless CLI with an MCP server on stdio, in headless mode or bridged to the running app.
- The core MCP tools are shared: `command_list`, `command_run`, `command_batch`, `doc_inspect`, `render_preview`,
  with resources `<app>://document` and `<app>://commands`.
- None of the three apps is single-instance on Windows or Linux. A second launch with file arguments starts a
  second process. Only PhotoCraft on macOS gets files sent to the already running process, through Apple events.

### 3. Command registry

- Spec: `crates/engine/src/commands.rs:15-28` (`CommandSpec {id,label,menu,shortcut,params,enabled,run,journal}`).
  `cmd!` is defined at `:129-133`. Registry build: `:398` with `v.extend(<module>::specs())` (`:1263-1360`). Lookup
  is `find()` at `:152`. `command.list` (`:1114-1120`) lists only the engine registry.
- UI-level ids (`view.*`, `window.*`, `file.open/save/saveAs`, …) are accepted by `engine.execute` in the desktop app
  but are not part of `command.list`. Sources: `crates/ui-egui/src/menus.rs:23-103` (`UI_COMMANDS`), and
  `is_live()` at `:931-946`, which also accepts ids from `view_cmds::handles`, `workspace_ui::handles` and others.
- Strict param checking applies only to the ids in `STRICT` (`crates/engine/src/param_check.rs`; `docs/control-protocol.md:79`).
- Over the control channel and MCP, `file.*` commands that take paths (`file.open`, `file.save*`, `file.automate.batch`,
  `file.scripts.imageProcessor`, …) are refused as "ambient filesystem paths". Use `app.open`/`app.save` or the
  `doc.*`/MCP scoped tools instead (`docs/control-protocol.md:160`; `crates/automation/src/workspace.rs`). The CLI
  `run`/`batch` subcommands use `Headless::trusted_local()` (`apps/photocraft-cli/src/lib.rs:300`), so paths work there.

### 5. Control channel

- Protocol: JSON lines over TCP on `127.0.0.1:<port>`. Transport: `apps/photocraft/src/control_server.rs:18-117`.
  Handlers: `crates/ui-egui/src/control.rs:1-33` (method list) and `:385-1250` (`dispatch`).
- Auth: the first frame must be `{"id":"auth","method":"auth","params":{"token":"<64 hex>"}}`. Without it the
  connection is closed (`control_server.rs:74-81`; `docs/control-protocol.md:20-26`).
- Limits: 1 MiB request line, 8 MiB reply, 16 connections, 30 s socket timeout, 60 s reply deadline. The two
  timeout errors are `timeout: not run` (safe to re-send) and `timeout: no reply in 60s`
  (`crates/automation/src/security.rs:17-19`; `crates/ui-egui/src/control.rs:47-67`; `docs/control-protocol.md:383-424`).
- Methods: `engine.execute`, `ui.menu.invoke`, `engine.commands`, `ui.inspect`, `ui.menu.list`, `ui.set`,
  `ui.dialog.open/set/confirm/cancel/apply`, `ui.window.open/close`, `ui.pointer`, `ui.click`, `ui.move`, `ui.key`,

  (`crates/ui-egui/src/control.rs:391-1250`).
- Targets the running GUI: yes. `app.open {path}` opens a file in the running app (`control.rs:1199-1236`), but only
  as a relative path under `--automation-read-root`. Absolute paths outside the root are refused

### 5. Control channel

- Protocol: JSON lines over TCP on `127.0.0.1:<port>`. Only request objects are read: a non-request line gets one
  error reply and the connection is closed (anti-HTTP smuggling). Limits: 4 MiB lines, 16 connections. A request
  is abandoned if no frame is drawn for 5 s; replies time out after 60 s
  (`apps/lightcraft/src/control_server.rs:1-140`; `docs/control-protocol.md:1-29`).
- **Auth: none** ("The port has no authentication", `docs/control-protocol.md:27`).
- Methods (`crates/ui-egui/src/control.rs:201-458`; `docs/control-protocol.md:60-87`): `engine.execute`
  (aliases `ui.menu.invoke`, `command`), `engine.commands`, `ui.menu.list`, `ui.menu.tree`, `ui.inspect`, `ui.widgets`,
  `ui.clickWidget`, `ui.dragWidget`, `ui.hoverWidget`, `ui.move`, `ui.click`, `ui.drag`, `ui.pointer`, `ui.key`,

- Targets the running GUI: yes, with absolute paths and no sandbox. Examples:

### 4. MCP server (`filmcraft-automation`, rmcp 3.5)

- Transport: stdio (`apps/filmcraft-cli/src/main.rs:481-492`). Headless: `filmcraft-cli mcp [--project p.fcproj | --demo]`.
  Bridge: `filmcraft-cli mcp --bridge 127.0.0.1:<port>`. Auth: none (the control channel has none either).
  Dependencies: `crates/automation/Cargo.toml:12-22`.
- Tools (17, `crates/automation/src/server.rs:306-547`): `command_list`, `command_run`, `command_batch`, `doc_inspect`,
  `render_preview`, `project_inspect`, `sequence_inspect`, `media_import`, `render_frame`, `ui_inspect`, `ui_elements`,
  `ui_click`, `ui_drag`, `ui_key`, `ui_type`, `ui_screenshot`, `ui_control` (any control method). The registry is
  reached generically through `command_run`.
- Resources: `filmcraft://document`, `filmcraft://commands` (`server.rs:590-591`). No prompts. Conventions and export
  progress/cancellation: `docs/agents.md` § Conventions (`docs/control-protocol.md:162-169`).

### 5. Control channel

- Protocol: JSON lines over TCP on `127.0.0.1:<port>`. The same request-only, close-on-junk policy as LightCraft:
  4 MiB lines, 16 connections (`apps/filmcraft/src/control_server.rs:1-60`; `docs/control-protocol.md:3-21`).
- **Auth: none** (`docs/control-protocol.md:16`).
- Methods (`crates/ui-egui/src/control.rs:103-463`): `engine.execute`, `ui.menu.invoke`, `engine.commands`,
  `ui.menu.list`, `ui.inspect`, `perf.stats`, `ui.elements {prefix?}`, `ui.set {tool, workspace, mode, theme, timeline,
  program, source, export, projectPanel, mediaBrowser, …}`, `ui.panel.show`, `ui.panel.close`, `ui.click`, `ui.move`,
  `ui.drag`, `ui.scroll`, `ui.key`, `ui.type`, `ui.timeline.hit`, `ui.timeline.locate`, `ui.playback`,
  `ui.screenshot {path?, panel?}`, `ui.resize`, `ui.focus`, `app.quit`.
- Example: `{"id":1,"method":"engine.execute","params":{"command":"sequence.addEdit","params":{"seconds":3}}}` →
  `{"id":1,"ok":true,"result":{"cuts":2}}` (`docs/control-protocol.md:19-22`).
- Targets the running GUI: yes, with absolute paths and no sandbox. Open in the running app with
  `engine.execute file.open {path}` or `file.import {paths}`, or from a shell with
  `filmcraft-cli --bridge 127.0.0.1:PORT exec file.import paths='["/abs/a.mov"]'`. Switch modes with the UI command
  `mode.export` or `ui.set {mode}` / `{workspace}`.
